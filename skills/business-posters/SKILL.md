# 经营海报

从用户已认证的 `ailit` 中读取数据，生成 `1080×1620` PNG 经营图片。当前支持“月度到账净收款日历”和“结论优先的三页经营月报”。

## 用户如何触发

用户无需会命令行，以下说法都应直接触发：

- “生成本月经营日历”
- “用经营海报做一张上个月的收款日历”
- “生成 2026 年 7 月经营海报”
- “生成本月经营月报”
- “把上个月经营情况做成三张手机海报”
- “把本月经营日历保存到桌面”

未指定月份时，默认为 `Asia/Shanghai` 时区的当前月；未指定保存位置时，保存到当前工作目录的 `经营海报输出/` 文件夹。

## 首次使用

1. 先运行 `ailit doctor --format json`。
2. 如果检查通过，直接生成，不要让用户重复登录。
3. 在 WorkBuddy Connector 环境中，如果未登录或未选默认店铺，停止生成并提示用户重新连接“经营海报” Connector；安装、登录和状态检测由 `cli.json` 管理。仅在普通终端/Codex 环境中，才请用户运行 `ailit auth login --workbuddy-auto-return`。
4. 不读取、复制或展示 token、手机号等认证信息。

## 模板路由

- “经营日历”“收款日历”“到账日历”：使用月度到账净收款日历。
- “经营月报”“月度经营分析”“本月经营情况”：使用三页经营月报。
- 只说“经营海报”且没有指定内容时，先用一句话确认要“收款日历”还是“经营月报”，不要同时生成两套。

## 收款类意图路由

- 用户问“开单时收了多少”“销售单本次实收”：读取销售单 `bill_pay_amt`。
- 用户问“销售单已收多少”“哪些单未结清”：读取销售单 `total_pay_amt/owe_amt/settlement_status`，回答这是当前单据状态。
- 用户问“后续回款”“收款单”：读取 `receipt list/get`，不改查销售单替代。
- 用户问“本月收款”“到账”“收款日历”：使用“销售单即时实收 + 独立收款单实际收款 − 销售退货实际退款”。
- 只有“查收款”且无更多上下文时，优先拆分展示“开单即时实收 / 后续收款单 / 净到账”。收款单金额与渠道已验证；若遇到尚未验证的优惠、预存款抵扣或退款字段，明确说明并停止，不猜测。
- 禁止把销售单 `total_pay_amt` 与独立收款单相加。详细字段与失败规则见对应数据契约。

## 经营日历生成方式

在本技能目录内运行：

```bash
node scripts/generate-calendar.mjs --month YYYY-MM --output <absolute-png-path>
```

- 当前月可省略 `--month`。
- 输出路径必须是绝对路径，扩展名必须是 `.png`。
- 只有用户明确需要可编辑文件时才加 `--keep-svg`。
- 只有用户明确需要标准化数据时才加 `--data-out <absolute-json-path>`；该文件包含经营数据。
- 如果本技能未带 `node_modules/sharp`，首次运行前在技能目录执行 `npm ci --omit=dev`。

生成成功后，向用户提供 PNG 文件和简短的月累计收款、收款天数摘要。不上传、不发送海报。

## 经营月报生成方式

生成前读取 [经营月报数据契约](references/monthly-report-data-contract.md)，然后运行：

```bash
node scripts/generate-monthly-report.mjs --month YYYY-MM --output-dir <absolute-directory>
```

- 当前月可省略 `--month`；默认输出到当前目录的 `经营海报输出/经营月报-YYYY-MM/`。
- 固定生成三张 `1080×1620` PNG：经营概览、货品与人员、资金与行动。
- 面向手机阅读，保持单列全宽卡片、累计趋势和横向排行，不把多组排行左右并列。
- 只有用户明确需要可编辑文件时才加 `--keep-svg`。
- 只有用户明确需要标准化数据时才加 `--data-out <absolute-json-path>`。
- 成功后提供三张 PNG，并摘要销售额、实收和经营利润；不上传、不发送。

## 月份与版式自适应

- 支持 28、29、30、31 天月份、闰年二月和跨年上月对比。
- 根据该月 1 日的星期自动定位，支持 4–6 行日历。
- 当前月只读取月初至今天，未来日期不显示金额；历史月读取完整自然月。
- 未来月份不生成，应说明原因并请用户改选月份。

## 月报后的连续问答与对账

- 用户基于月报继续询问“客户欠款”“欠款明细”或“为什么本月销售单待收与客户欠款不一致”时，继续使用 `ailit` 查询真实数据，不只读取海报文字或历史 JSON。
- “本月销售单待收”是报告期内有效销售单当前待收，包含系统默认散客；“客户欠款”是生成时命名客户的欠款余额快照，可包含期初和历史余额。两者不是同一口径，不要求相等，也不能直接用差额推断某一类欠款。
- 用户从月报点名欠款客户并要求对账时，先查询并消歧，再取明细：

```bash
ailit report customer-check list --keyword "<客户名>" -s YYYY-MM-DD -e YYYY-MM-DD --format json
ailit report customer-check detail <company-id> -s YYYY-MM-DD -e YYYY-MM-DD
```

- 用户要求导出官方客户对账单 PDF 时运行：

```bash
ailit customer print pdf <company-id> -s YYYY-MM-DD -e YYYY-MM-DD --format json
```

取得 URL 后下载到用户指定位置；未指定时保存到当前工作目录的 `经营海报输出/对账单/`。核对客户、日期、期初、本期应收、本期实收和累计欠款；文件实际存在且大小大于 0 后才能报告已导出。列表、明细和 PDF 金额不一致时停止交付并说明差异。

## 数据与安全边界

- 只运行对应数据契约中列出的只读命令。
- CLI 失败、JSON 结构变化、字段不支持、分页不完整或交叉校验失败时，停止生成；不将错误当成 0 元。
- 金额以整数分累计，指标和经营提示由脚本确定生成。
- 保持现有固定版式、品牌资产和二维码；用户没有要求改版时不调整视觉。

修改数据适配或指标口径前，先读取 [日历数据契约](references/calendar-data-contract.md)。

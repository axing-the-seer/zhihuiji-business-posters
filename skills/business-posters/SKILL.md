# 经营海报

从用户已认证的 `ailit` 中读取数据，生成 `1080×1620` PNG 经营图片。当前支持“月度到账净收款日历”和“结论优先的三页经营月报”。

## 用户如何触发

用户无需会命令行，以下说法都应直接触发：

- “生成本月经营日历”
- “用经营海报做一张上个月的收款日历”
- “生成 2026 年 7 月经营海报”
- “生成本月经营月报”
- “把上个月经营情况做成三张手机海报”
- “把本月经营日历保存到桌面”

未指定月份时，默认为 `Asia/Shanghai` 时区的当前月；未指定保存位置时，保存到当前工作目录的 `经营海报输出/` 文件夹。

## 初始化与用户沟通

- 面向用户统一称“智慧记AI进销存”。需要说明子功能时，称“智慧记AI进销存的经营月报能力”或“智慧记AI进销存的客户对账能力”；不可省略产品名，也不要把页面类型误说成产品。
- 生成脚本会完成连接、登录态、默认店铺和数据一致性检查；不要在调用脚本前单独运行 `ailit doctor` 或 `ailit auth status`，避免重复检查和偶发结果不一致。
- 用户明确要求“经营日历”或“经营月报”时直接生成。执行期间最多回复一句“正在通过智慧记AI进销存读取经营数据并生成……，请稍等”，不要逐步播报内部检查。
- 只说“经营海报”且无法判断类型时，用业务语言确认：“经营日历是 1 张每日实际收款图；经营月报是 3 张经营概览、商品与库存、收款与客户。你要哪一种？”
- 不向用户展示或解释命令、数据契约、CLI、doctor、JSON、npm、Sharp、node_modules、PATH、脚本、重试过程或内部字段名。
- 脚本失败时只读取结果中的 `user_message` 告知用户，不转述 `internal_error`、`details`、命令输出或自行排查过程。可重试错误由脚本内部处理；失败后不要反复运行。
- 在 WorkBuddy Connector 环境中，如果未登录或未选默认店铺，提示用户重新连接“经营海报” Connector或先在智慧记中选择店铺。仅在普通终端/Codex环境中，才请用户运行 `ailit auth login --workbuddy-auto-return`。
- 不读取、复制或展示 token、手机号等认证信息。

## 模板路由

- “经营日历”“收款日历”“到账日历”：使用月度到账净收款日历。
- “经营月报”“月度经营分析”“本月经营情况”：使用三页经营月报。
- 只说“经营海报”且没有指定内容时，按“初始化与用户沟通”的文案确认一次，不要同时生成两套。

## 收款类意图路由

- 用户问“开单时收了多少”“销售单本次实收”：读取销售单 `bill_pay_amt`。
- 用户问“销售单已收多少”“哪些单未结清”：读取销售单 `total_pay_amt/owe_amt/settlement_status`，回答这是当前单据状态。
- 用户问“后续回款”“收款单”：读取 `receipt list/get`，不改查销售单替代。
- 用户问“本月收款”“到账”“收款日历”：使用“销售单即时实收 + 独立收款单实际收款 − 销售退货实际退款”。
- 只有“查收款”且无更多上下文时，优先拆分展示“开单即时实收 / 后续收款单 / 净到账”。收款单金额与渠道已验证；若遇到尚未验证的优惠、预存款抵扣或退款字段，明确说明并停止，不猜测。
- 当前仅验证数值 `status=1` 的有效收款单；出现其他状态时停止生成，不计入也不忽略。当前尚未取得真实非空退货样本，本期或对比期出现销售退货时停止生成，不猜测退款字段。
- 禁止把销售单 `total_pay_amt` 与独立收款单相加。详细字段与失败规则见对应数据契约。

## 经营日历生成方式

在本技能目录内运行：

```bash
node scripts/generate-calendar.mjs --month YYYY-MM --output <absolute-png-path>
```

- 当前月可省略 `--month`。
- 输出路径必须是绝对路径，扩展名必须是 `.png`。
- 只有用户明确需要可编辑文件时才加 `--keep-svg`。
- 只有用户明确需要标准化数据时才加 `--data-out <absolute-json-path>`；该文件包含经营数据。
- WorkBuddy安装阶段应已准备渲染依赖；生成过程中不要临时安装依赖。普通终端环境若缺少依赖，只提示“经营海报服务尚未完成初始化”，不要把安装命令发给普通用户。

生成成功后，向用户提供 PNG 文件和简短的月累计收款、收款天数摘要。不上传、不发送海报。

## 经营月报生成方式

生成前读取 [经营月报数据契约](references/monthly-report-data-contract.md)，然后运行：

```bash
node scripts/generate-monthly-report.mjs --month YYYY-MM --output-dir <absolute-directory>
```

- 当前月可省略 `--month`；默认输出到当前目录的 `经营海报输出/经营月报-YYYY-MM/`。
- 固定生成三张 `1080×1620` PNG：经营概览、商品与库存、收款与客户。
- 面向手机阅读，保持单列全宽卡片、累计趋势和横向排行，不把多组排行左右并列。
- 只有用户明确需要可编辑文件时才加 `--keep-svg`。
- 只有用户明确需要标准化数据时才加 `--data-out <absolute-json-path>`。
- 成功后提供三张 PNG，并使用页面上的业务名称摘要“本月销售额、本月利润、本月实际收款”；不上传、不发送。
- 默认回复说明数据截止日期和三个页面的内容，不主动介绍 SVG、JSON、命令参数或实现细节。只有用户明确索要时才说明额外输出。
- 历史月报的交付回复应说明：“销售、利润和进货按报告月份统计；客户欠款、库存和销售单待收按本次生成时的最新情况显示。”不要使用“快照”等技术词。
- 保留页面“毛利率”和“回款率”名称。交付回复补充：“图中的毛利率按本月利润占销售额的比例计算；回款率按本月实际收到的金额除以本月销售额计算，其中可能包含本月收回的以前欠款，因此有时可能超过 100%。”

推荐的页面说明：

- 经营概览：本月销售额、本月利润、总支出、经营建议、实收金额、销售单数和销售趋势。
- 商品与库存：进货统计、商品销量、商品利润、低库存和缺货商品。
- 收款与客户：本月实际收款、收款渠道、回款率、本月销售单待收、客户欠款和销售贡献。

## 月份与版式自适应

- 支持 28、29、30、31 天月份、闰年二月和跨年上月对比。
- 根据该月 1 日的星期自动定位，支持 4–6 行日历。
- 当前月只读取月初至今天，未来日期不显示金额；历史月读取完整自然月。
- 未来月份不生成，应说明原因并请用户改选月份。

## 月报后的连续问答与对账

执行前读取 [客户对账单数据契约](references/customer-statement-data-contract.md)。

- 用户基于月报继续询问“客户欠款”“欠款明细”或“为什么本月销售单待收与客户欠款不一致”时，继续使用 `ailit` 查询真实数据，不只读取海报文字或历史 JSON。
- “本月销售单待收”是报告期内有效销售单目前还没收回的金额，包含系统默认散客；“客户欠款”是本次查询时命名客户的最新欠款余额，可包含以前月份的余额。两者统计范围不同，不要求相等，也不能直接用差额推断某一类欠款。
- 用户从月报点名欠款客户并要求对账或导出 PDF 时，使用安全执行脚本完成客户查找、明细核对和官方 PDF 下载。客户名称、日期和保存位置通过标准输入传入 JSON，绝不拼进 Shell 命令：

```bash
node scripts/reconcile-and-export-statement.mjs
```

- 标准输入结构固定为 `{"customer":"客户名","start":"YYYY-MM-DD","end":"YYYY-MM-DD","output":"绝对 PDF 路径"}`。用户从候选客户中确认后，可增加 `company_id` 再执行一次；不要把内部客户编号展示给用户。
- 默认沿用当前月报的日期范围；用户未指定保存位置时保存到当前工作目录的 `经营海报输出/对账单/`。只有找到多个同名或相近客户时才询问一次，其余步骤静默完成，不重复确认用户已经给出的客户、月份和导出意图。
- 需要告知执行状态时说“正在通过智慧记AI进销存核对客户欠款并准备对账单，请稍等”，不要省略产品名。
- 脚本会核对客户、日期、逐笔单据金额、本期实际收款、本期账款变动、期初欠款和累计欠款，限制可信下载地址，验证 PDF 文件格式并完成后再写入正式文件。只有 `ok:true` 且文件已存在时才能报告“已导出”；任何金额或文件校验失败都停止交付。

## 数据与安全边界

- 只运行对应数据契约中列出的只读命令。
- CLI 失败、JSON 结构变化、字段不支持、分页不完整或交叉校验失败时，停止生成；不将错误当成 0 元。
- 金额以整数分累计，指标和经营提示由脚本确定生成。
- 保持现有固定版式、品牌资产和二维码；用户没有要求改版时不调整视觉。

修改数据适配或指标口径前，先读取 [日历数据契约](references/calendar-data-contract.md)。
